## 0. 一页摘要（给汇报用）

- **定位 ⟐（档位待师哥拍）**：**方法为重心 + 实证研究提供依据/评估**。备选档位：①方法为主、实证为辅（倾向）；②实证与方法并重；③实证为主、方法为辅。本文按档①写，可下调。
- **一句话贡献**：现有 rubric 生成方法几乎都**基于单个模型**；我们**通过实证研究**揭示单模型生成的 rubric 存在**跨模型部分互补**的系统性局限（不同模型漏不同侧面，但也共享一个盲区核），据此提出一个 **training-free 的跨模型族 rubric 组装方法**，并证明其覆盖增益**来自跨模型互补、而非单纯堆量**，增益上限由共享盲区界定。
- **核心 insight**：LLM 生成的 rubric 是对真实评价标准的**部分建模**。多个部分建模能否拼得更全，取决于它们漏的是不是同一批侧面——**互补的部分让多模型有救，共享的盲区核决定它的天花板**。

## 2. 背景

- Rubric（细粒度评价标准）正在成为 LLM 评测与 RL 奖励的主流载体（LLM-as-judge、rubric-as-reward）。
- 高质量 rubric 依赖专家，难以覆盖扩张的任务空间，于是“让 LLM 自动生成 rubric”成为热点（Auto-Rubric / RocketEval / CheckEval / TICK / OpenRubric 等，见 `10.18653/v1/2026.acl-long.1439`）。
- **已被确立的前提（不再是我们的发现）**：单个 LLM 生成的 rubric 对专家金标准的**覆盖显著不足**——RubricBench Rubric Recall 仅 26.3%–53.8%、Hallucination 54–76%（`10.18653/v1/2026.acl-long.1439`）；RubricRAG Missed@0.2=56.4%（`2603.20882`）；多管线 Miss 0.342–0.474（`EnWBxpAKPd#cov`）。≥6 个同构念独立测量佐证。

## 3. 动机（叙述主线：单模型 → 实证 → 多模型）

**① 现状地貌：现有 rubric 生成方法几乎都基于单个模型。** Auto-Rubric / RocketEval / CheckEval / TICK / OpenRubric、以及 training-free 的精炼管线（`2610.38220` Rubricon），无论是单次生成、同模型多次采样还是同模型多角色（`2607.01830` MRRG），**优化的都是“把一个模型用好”**。

**② 实证点出单模型的局限——而且这个局限是“跨模型部分互补”的。** 单模型覆盖不足已是共识（Rubric Recall 26–54%，`...acl-long.1439`），但真正决定下一步的，是一个**从未被测量**的事实：不同模型族漏掉的**不是同一批侧面**，而是**部分互补**的——A 漏的 B 往往有。现有工作只测“单生成器 vs 单金标准的聚合覆盖率”，**从不比较跨模型的漏集**（`...acl-long.1439` 明确“各自单流水线、无跨生成器对比”）。我们的实证就是补这个空白：测**跨模型 missed-set 的互补程度（φ/Jaccard vs 独立零模型）**。

**③ 因此引出多模型。** 既然单模型的漏是部分互补的，**组合多个模型族的 rubric** 就能把 A 的缺口用 B 补上——这是方法的直接动机，也是单模型范式**结构上做不到**的事。

**④ 但有一个诚实的上限：共享盲区核。** 并非所有缺口都互补——存在**所有模型都漏的同一批侧面**（系统性盲区），多模型补不回来。强旁证：omission 抗审计且跨十个生成器一致（`2608.01000`）、“缺失事实”判别跨 2 族近随机（`2608.31016`）、rubric 可利用性跨厂商、per-type 剖面一致（`2609.16816`）、同几类 rubric 对 4 族都难（`2603.25133#types`）。所以多模型的增益**有天花板**，而刻画这个天花板正是让我们的增益**可信、可归因**的关键（否则会被 ConRub-Med 交集共识缩集反例 `2608.10996`、Rubricon 裸并集被反超 `2610.38220#merge` 这类“组装≠互补”的教训反驳）。

> 一句话：**互补性让多模型有救（动机）；系统性盲区决定它补到哪为止（上限/诚实边界）。**

## 4. 核心 insight

1. LLM 生成 rubric = 对真实准则集的**部分建模**（已确立前提，非贡献）。
2. 多个部分建模能否拼出更完整的图，取决于漏集是否正交：**正交/互补 → 多模型有效；相关/共享 → 多模型失效**。真实情况是两者并存——有互补部分，也有共享盲区核。
3. 因此方法的科学问题不是“组装有没有增益”（已被占、已死），而是**“增益是否来自跨模型互补，而非单纯堆更多准则/更多采样”**——这需要**边际覆盖曲线 + 独立零模型 + 同模型堆量基线**才能归因。这正是把我们的方法与“更多 rubric 更好”区分开的东西。

## 5. 研究问题与假设（收口版，按“实证支撑方法”组织）

**RQ**：跨模型族生成的 rubric 漏集呈现怎样的互补/共享结构？能否据此设计一个 training-free 的跨模型组装方法，使准则级覆盖的增益确实来自互补而非堆量，并刻画其上限？

**实证发现（动机与归因，支撑方法）**

- **E-互补（引出多模型的关键发现）**：不同模型族的 rubric 漏集**部分互补**——跨模型 missed-set 的 φ/Jaccard **显著低于“完全重合”、高于“完全正交”**，即存在可被组装利用的互补缺口。
  - 证伪：漏集几乎完全重合 → 共享盲区主导、多模型无救 → 整条方法动机塌，需回退。
- **E-系统性/上限（界定天花板，非动机）**：同时存在**所有模型共享的盲区核**（漏集重合显著高于独立零模型的那一部分），多模型并集覆盖因此**存在饱和上限**。
  - 可观测：union coverage(k) 曲线趋于饱和；饱和水平 < 1（共享盲区 > 0）。

**方法主张（重心 ⟐）**

- **H-方法**：我们的跨模型组装器使**准则级覆盖 > max(single)**，且其增益**显著高于同模型堆量基线**——即增益来自**跨模型互补**。
  - 必比基线：同模型重复采样并集（`2610.38220#merge`）、同模型多角色（`2607.01830` MRRG）、交集共识（`2608.10996`）。
  - 证伪：跨模型并集曲线 ≈ 同模型采样曲线 → 增益只是堆量，方法无独立价值。

**已砍**

- **H2（覆盖差异→bias）**：⟐ **本轮砍掉**，不投预算。理由：强版本有反证（仅“作者标签”即可双向移动分数 `2608.18091`），窄版本门槛过高（内禀覆盖 + 全套混淆控制 + 增量方差）。保留为未来可选次线。

## 6. 方法 ⟐

**本质**：training-free framework + 旗舰模型驱动（不吃算力，契合 ACL 节奏与实验室条件）。

- **方法层（重心）**：一个**显式利用跨模型互补性**的 training-free 跨模型族 rubric 组装器。
  - 核心设计 ⟐：按**“边际新覆盖”**而非“多数共识”保留准则——直接针对 ConRub-Med 交集共识缩集的失败模式（`2608.10996`）与 Rubricon 裸并集被反超的问题（`2610.38220#merge`）。
  - 关键验证不是“比单体好”（已死），而是“**比同模型堆量基线好、且好在覆盖的互补部分**”。
  - 方法该做多重由 §11-Q4 定档：是“归因工具级的轻组件”还是“有竞争力的独立方法贡献”。
- **测量/评估层（为方法提供依据与度量）**：
  - 固定任务集与**单套 operational 专家金标准**（不做金标准效度研究，见 §9 诚实边界）。
  - N 个异质模型族各自独立生成 rubric → 用一个**独立的等价判定器**把每条生成准则对齐到金标准准则（判定器**禁止与任一生成模型同族**，规避 `2611.25557#a` 的自兼任弱点）。
  - 每模型得 covered/missed 二元指示向量 → 算跨模型 **φ/Jaccard**、对照**独立零模型**（蒙特卡洛，形式借 `2605.29800` 的 Kish/Condorcet）→ 支撑 E-互补 / E-系统性。
  - 算 **union coverage(k)** 曲线与饱和上限（上限形式可借 `2610.03025` 的 Good–Turing whisker，但**不做成贡献**，只做归因与上限刻画）。

## 7. 实验方案

- **数据/金标准**：PRBench（1,100 任务 / 18,711 准则，`10.18653/v1/2026.acl-long.1958#gt`）为主；HealthBench（`2505.08775`）、ResearchRubrics（`2511.07685`）、ClinConsensus（`10.18653/2026.findings-emnlp.1339`）做跨域复现。均为**每任务单套参照**（足够支撑零模型路线，见 §9）。
- **生成器**：≥4 个异质模型族（如 GPT / Claude / Gemini / Qwen / DeepSeek 各旗舰），确保“跨模型族”而非同族采样。
- **核心指标**：Rubric Recall（覆盖率，`...acl-long.1439` 的三件套）、cross-model missed-set φ/Jaccard（vs 零模型）、union coverage(k) 曲线与上限。
- **必做基线（novelty 防御的关键）**：
  - 同模型重复采样并集（`2610.38220#merge`）
  - 同模型多角色（MRRG，`2607.01830`）
  - 交集共识（ConRub-Med，`2608.10996`）
- **消融/控制**：匹配判定器换族做鲁棒性；加权 vs 未加权覆盖（`2610.19915` 提示必须声明）；准则依赖的图覆盖 vs 集合覆盖一阶近似（`8aJzGgbRDL#dep`）。
- **下游验证（次要，呼应 idea-2）**：生成 rubric 用于(a) GRPO 奖励、(b) 并行挑选回答、(c) 串行 TTS 指导——证明“覆盖结构”的实用后果，但不作主张主体。

## 8. 现状地貌与我们的位置（叙述用，带指针）

把已有工作摆成一张“单模型 → 多模型”的地图，我们的动作是其中唯一的空位，而不是去躲谁：

| 现状地貌（已做到哪）                      | 代表工作                                 | 我们的位置                                                         |
| ----------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------ |
| 单模型 rubric 生成，覆盖已知不足          | `...acl-long.1439` 等                    | 以此为**前提**，不重复测                                           |
| 同模型多次采样 / 多角色组装               | `2610.38220` Rubricon、`2607.01830` MRRG | 仍是**单模型范式**；我们迈向**跨模型族**                           |
| 两系统并集单点、下游分数                  | `2611.25557#b`                           | 我们给**准则级、随 k 的覆盖曲线**                                  |
| 并集+上限（行为标签分母、共享同一 judge） | `2610.03025`                             | 我们分母是**专家金标准**、轴是**多模型族**，且上限只做归因不做卖点 |
| 跨模型**交集**共识（缩集、反例）          | `2608.10996` ConRub-Med                  | 我们取**边际新覆盖**，并直接测“增益来自互补”                       |

## 9. 风险与诚实边界

- **金标准 = operational reference**：我们**不研究其效度、不分解“模型缺陷 vs 人类噪声”**（无同任务多专家 rubric 集合数据，Delphi360 `10.1186/...1071-x` 是唯一集合级来源但 n 太小）。结论表述为“相对专家参照的覆盖/重合结构”，不声称绝对真值。系统性靠**零模型**顶住，不靠第二位专家。
- **匹配判定器**是方法学攻击面 → 换族消融 + 人工抽验。
- **准则不独立** → 需在报告依赖结构处用图覆盖补充集合覆盖。
- **OpenAlex 补检残留**：引用图已在 R11 对 4 篇高被引闭合，但“无人测过”始终是**检索意义**的空白。
