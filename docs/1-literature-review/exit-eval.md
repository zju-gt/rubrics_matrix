## 4. 子域 mismatch / failure-mode notes（汇总；全文见 `findings.md` §7）

- **D1**：最关键的错位是**测量层次**——现有工作报聚合覆盖率（单生成器 vs 单 gold），不测漏集的重合结构，也不把专家 rubric 自身的完备性当变量。
- **D2**："multi" 在文献里有三种含义（同模型多次采样 / 同模型多角色 / 多模型合并）；只有多模型合并在构念上接近我们，且它只报下游分数、不测准则级覆盖/重叠。
- **D3**：几乎所有生成方法优化下游准确率；覆盖率最多是"动机陈述"，不是被测量对象。
- **D4**：所有 SPB 研究都固定评价工具，因此"覆盖差异"自变量被设计消掉；H2 的构念在他们的设置里不可见。
- **D5**：所有专家一致性指标都是"给定准则后判 met/not-met"，不是"独立写出的准则集合是否重合"；golden-rub 的完备性从未被当作可测量对象。

## 6. 交给用户的决策点

1. **是否接受"仅 P1(a) 判死、其余重立靶"的范围化裁定？** 注意 R11 后 P1/P3 的存活贡献已进一步收窄：只能主张"以专家 golden-rub 为分母、跨 LLM backbone、准则级"的覆盖/并集测量；不能再主张"首个把覆盖不完备做成可测/可界定量"或"首个做并集上限"（`2610.03025`）。若接受，下一步是把 `findings.md` §8 的三条改写写入 `TODO.md` 的 H1/H2。
2. **golden-rub 选用哪个来源？** 候选：PRBench（1,100 任务/18,711 准则，专家-专家 κ=0.589）、HealthBench（医生撰写）、ResearchRubrics、LEGIT（法律，α=0.87）、RubricBench（atomic 专家准则）。注意任一来源都需先做效度审计（权重反校准、集合级一致性、标注噪声下界）。
3. **H2 保留为窄版本，还是降为次要探索？** 证据倾向：窄版本可做但门槛很高（内禀覆盖 + 全套控制 + 增量方差）；强版本（展示 rubric 的覆盖差异→SPF）已有反证。
4. **是否进入"测量对象与协议"阶段？** 若进入，建议先解决：覆盖率的分母（golden-rub 如何审计）、匹配协议（禁止同模型兼任等价判定）、加权/未加权、依赖结构（图覆盖 vs 集合覆盖）、标注噪声扣除。
