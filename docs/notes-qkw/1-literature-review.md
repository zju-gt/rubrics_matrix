- 六个调研维度：覆盖率、重叠率、系统性、组装增益、bias成因、金标准效度
  1. **覆盖率**：single-rub 各自覆盖率是否 <1
  2. **重叠率**：single-rub 之间覆盖重叠率低（存在互补性）
  3. **系统性**：single-rub 之间覆盖重叠率高（互补性低、存在同一批评价标准侧面被各个模型生成的rub都覆盖不到）
  4. **组装增益**：multi-rub 的组装存在优势、优势有上限
  5. **bias成因**：重叠率低的各个覆盖之间的差异可以部分解释bias
  6. **金标准效度**：single-rub 的低覆盖率是否是因为 golden-rub 本身不可靠（存在标注噪声）
- 各维度调研结果：
  1. **覆盖率**：single-rub 各自覆盖率是否 <1
     - 结果：显著 <1 （至少 6 个同构念工作独立测得）。
     - 结论：从“需要实验验证的现象”降级为“**已确立的前提**”。
  2. **重叠率**：single-rub 之间覆盖重叠率低（存在互补性）
     - 结果：完全空白。——没有**任何一篇**计算了“不同模型生成的 rubric 各自漏掉哪些准则、这些集合是否重合”。
     - 结论：可以设置实验并作为核心贡献之一。
  3. **系统性**：single-rub 之间覆盖重叠率高（互补性低、存在同一批评价标准侧面被各个模型生成的rub都覆盖不到）
     - 结果：只有旁证。——多篇论文指向“存在这样的侧面”，且有一篇工作对它做了定量实验。
       - 2608.01000(omission 主导)
       - 2608.31016(judge对"缺失事实"的判别近随机 0.50–0.63)
       - 2609.16816(失败跨厂商、per-type profile在环境内一致)
       - 2603.25133#types(Format/Role 类约束对所有 judge family都难)
       - 2610.03025 用 capture–recapture / Good–Turing missing mass 把"未被任何 rubric 发现的准则值多少钱"做成了可界定量——所以不能声称"首个把覆盖不完备做成可测量"。
     - 结论：需要讨论。
     - 工作设想：
       - 或许可以基于 2610.03025 声称已有测量过的组装增益上限（金标准覆盖区域 - 覆盖不到的区域）、我们不重复测量
       - 或许我们可以基于“金标准也有标注噪声”（见第6个调研维度）来进一步把随机噪声引入分析框//架，并据此设计测量方法来进一步得到更合理的上限。
  4. **组装增益**：multi-rub 的组装存在优势、优势有上限
     - 结果：已有做组装的论文，且存在分析组装增益上限的论文；还有一堆杂七杂八的结论，需要进一步理解。
     - 结论：不Novelty，但据称仍有存活的路线，需要进一步理解。
  5. **bias成因**：重叠率低的各个覆盖之间的差异可以部分解释bias
     - 结论：不太能解释（见2608.18091）、需要复杂限定条件才能成立。这一假设成立与否不影响主要工作，因此我们接下来不再考虑这一假设。
  6. **金标准效度**：single-rub 的低覆盖率是否是因为 golden-rub 本身不可靠（存在标注噪声）
     - 结果：专家 rubric ≠ 可靠真值，必须先审计。
     - 结论：接下来做测量之前，必须先做效度审计，把标注噪声算进去，否则测量结果分不清是模型缺陷还是标注噪声。
     - 疑惑：既然专家rubric并不可靠，而评测一个rubric好坏的方法又必须依赖专家rubric，那么之前的所有需要评测rubric好坏的工作难道都没意识到这一点吗？

## 附录

### 1. 系统性的各旁证：支持什么、缺少什么

① 2608.01000(authoring vs execution 不对称) — 最强的机制旁证。

- 证明了:模型"写出完整集合"的能力系统性低于"判断单点";遗漏是主导且抗审计的错误——植入的over-inclusion 被检出率是 omission 的 6–7 倍;生产语料里 10 个生成器的答案键错误omission:over-inclusion ≈ 10:1,且"十个生成器一致"。同模型重采样补不回漏掉的成员(K=16 unionrecall 仅 0.71–0.84)。
- 缺什么:它的集合是"可接受成员"(词表/代码解),不是 rubric 准则;而且无任何跨模型 Jaccard/共现矩阵——"一致"只是现象方向,不是重合统计。代码那条还朝相反方向失败(过度规定),说明omission 故事是构念特定的。

② 2608.31016(临床笔记 omission 判别) — 最干净的"遗漏难检"证据。

- 证明了:8 种 judge 设计对"缺失事实"的 paired 判别全在随机附近(0.50–0.63),对"增改"却0.79–0.94;投票/改写/GEPA 都救不回来。这个不对称跨 2 个模型族复现。
- 缺什么:测的是"judge 检不检得出被漏事实",不是生成 rubric 的准则集覆盖;而且 8 设计共用同一个 GPTjudge,附录明说"不支持 family-vs-family 比较"——没有跨模型漏集统计。

③ 2609.16816(不可能任务的 rubric 可利用性) — 跨厂商失败的证据。

- 证明了:11 个生成器被利用 8–26%,失败跨厂商(DeepSeek 与 Opus 的 per-type失败剖面在每种类型内一致、DeepSeek 与 GPT-5.5 在 32/45 环境上一致),失败按任务类型集中(证据不足型52–60%)。
- 缺什么:因变量是"可利用性",不是覆盖率;从不枚举"漏了哪些金标准准则";跨生成器的重合在环境/类型层,作者归因于环境难度——而这正是我们 P1(b) 必须控制的混淆。

④ 2603.25133#types(按 rubric 类型的 judge 准确率) — 最接近"共享盲区"但只到类型层。

- 证明了:4 个模型族对同几类 rubric(Format Structure、Role Persona)一致地差。
- 缺什么:只报边际准确率,无 per-item 跨族重合统计、无漏集交集;而且类型分类是 GPT-5.1打的,可能是标注器的 artifact。调研自己把它标成 orthogonal——"系统性 plausible 的提示,仅此而已"。
